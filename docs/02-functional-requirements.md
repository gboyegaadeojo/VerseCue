# Functional requirements

2026-11-17. Proposed review baseline. **Every connector, content, theme, Look, routing, output, readback and integration-dependent behavior in this document is PROVISIONAL; P0 PENDING.** A requirement is not a statement of available API capability. The original discovery phase did not authorize implementation; IFC has since authorized provisional implementation. This does not pass P0 or release gates. Current source/test evidence and remaining work are recorded in the [original requirement audit](99-original-requirement-evidence-audit.md); all requirements and acceptance criteria below remain unchanged.

MoSCoW applies within planned release: M=Must, S=Should, C=Could, W=Won't initial release. MVP cannot silently defer an M. Dependencies: A=audio/OS capture; S=STT adapter; P=parser/metadata; V=validated P0 connector; L=rights/installed translation mapping; U=UI; C=config/security. Test `T-FR-nnn` is the requirement-specific acceptance case executed under docs/06, with the Given/When/Then below plus its domain suite. Roles: audio, speech, parser, UX, integration, security, operations, product. BR mapping in final column; release is earliest delivery, not claim of completion. Safety controls are always enforced when their dependent feature exists.

## Requirement audit and release interpretation
FR-001–062 cover all minimum Section 6 categories with rationale, priority, dependencies, measurable acceptance, owner and phase. Tests T-FR-001–062 and scenario suites are defined in docs/06; traceability is finalized in docs/12. No row claims a supported endpoint that has not passed P0. Advanced ranges/context/edit/manual/history remain v1 while MVP safely rejects unsupported references; basic invalidation/context resets remain mandatory safety controls. Optional compact/global/discovery features cannot compromise thin-slice readiness.
