# Preparation with an already authorized input

2026-11-18. Draft PR22, source 0.6.0. This implements background lease retention for the normal Confirm passage workflow without granting Auto, starting a microphone or claiming live-service acceptance.

## State transitions and safeguards

When normal native passage preparation begins with an already active authorized input in **Confirm**, the controller cancels the current recognition worker, disarms output and clears stale session/context state while retaining the existing input lease and background suspension protection. Buffered input can continue. No microphone permission request, device substitution or automatic reacquisition is introduced. With no active input, Auto or a legacy Advanced preparation request, the original pause/cancel behavior remains.

All output still goes through the coordinator operation lock, fresh passage review and explicit confirmation. New references/corrections cancel pending native work; ordinary sermon speech does not invalidate an unchanged reviewed passage. Hold/ignored-navigation and ambiguous parser evidence invalidate review context. A new reference still invalidates previous continuation even after dismissal. Auto retains its stricter new-speech correction guard.

Suggest-only intent survives native preparation: changing the session to Paused during preparation cannot grant permission to show a Suggest-only review. The operator must deliberately resume Confirm and prepare again. Stop, Pause, input/context loss, owner-window loss, sleep/recovery and relevant target health changes cancel capture/preparation as appropriate. Recovered links do not silently resume listening or rearm output.

## Background passage ownership

The existing two-second connection health loop now also checks a verified current passage through read-only presentation fingerprint, cue identity and current-text reads. A changed or unverifiable output withdraws the review/continuation context, disarms, pauses and releases capture. It never restores the previous output, triggers a cue or changes the operator's material. Resume and fresh review are deliberate. Checks skip dry runs, missing context and active operations; an old asynchronous result cannot pause a newer target, context or operation. This does not make polling atomic with a subsequent output command; the existing immediate send preflights remain required.

317 module tests include unchanged ownership, manual takeover, content changes, late-result races and busy/dry-run exclusions. The synthetic desktop next-verse check now detects takeover and revoked capture without issuing another reference or confirmation. Its backend condition uses bounded polling; a bridged asynchronous browser predicate did not reliably wait for this transition. No real Companion, microphone or physical output acceptance is claimed.
