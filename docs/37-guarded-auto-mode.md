# Guarded Auto mode

2026-11-18 UTC, development0.4.0. User requested the missing Auto control. This PR is stacked on the sleep/wake-recovery PR so that power transitions revoke Auto safely. **This is supervised development/test output, not a P0 or church-service readiness pass.**

Auto is now selectable through a separate acknowledgment dialog. Confirm remains the startup/reset/resume default and Auto is never saved in settings/profiles. Dry-run Auto simulates commands with zero output requests. Actual-output Auto requires an armed loopback test instance and at least one saved, single-cue presentation explicitly attested for Auto: the complete passage must fit that cue with correct text, installed translation, theme and Looks. Ordinary Confirm mappings do not authorize Auto; split/multiple-cue presentations are rejected for Auto attestation. Arbitrary Bible lookup, LAN Auto and audience fidelity remain unverified.

Only the authorized local speech pipeline can schedule Auto. Eligibility requires a final utterance ending in silence, no dropped audio in the capture session, known recognition duration of at most4seconds, one valid KJV-numbered explicit reference within range limits, no parser warnings, no relative/corrected/quoted/manual reference, and an explicit current show/read/turn-to instruction. Discussion markers, duplicates, ambiguous/multiple references, unknown numbering, missing mappings and slow or truncated windows remain reviewable without automatic output. These deterministic predicates are heuristic safety controls, not calibrated correctness probabilities or measured accent accuracy.

A750ms correction grace precedes dispatch. New speech even without a reference, revision, expiry, queue change, stop, mode/configuration change, microphone release or sleep invalidates pending work. The dispatch guard is rechecked after asynchronous version/fingerprint reads and immediately before a trigger. At most one command is in flight. Uncertain/failed dispatch pauses and disarms Auto, with no write retry. Readback is distinguished from physical output observed. A command already accepted by ProPresenter cannot be retracted.

Quote suggestions remain desktop-confirmation-only under FR-025. Manual references and private API submissions cannot cause Auto scheduling. The operator may deliberately confirm a review-only candidate while in Auto; that is an explicit manual action, not an automatic quote trigger. No API can enable/rearm Auto.

Tests: the full170case regression suite passes, including grace scheduling, zero-write simulation, verified-cue dispatch, excluded speech classes, slow/dropped/truncated input, duplicate suppression, stale/stop/revision cancellation, async preflight changes, unmapped/LAN rejection and split-cue attestation rejection. Audio-buffer tests distinguish silence completion from a forced window limit. Source desktop Auto integration passed the actual enabled option/consent dialog, synthetic recognition-driven simulation, one automatic fake-target cue/readback while minimized, and cancellation by Stop/simulated suspend. No microphone, real ProPresenter or actual computer sleep was used; synthetic results are not speech accuracy evidence. Reproduce with `node scripts/test-guarded-auto.cjs [packaged-executable]`.

Full native/Mac/MOTU/physical Look/concurrent media/held-out recognition/false-display acceptance remains pending. The existing installed Bible/theme clipping findings are not bypassed. This implementation does not silently promote the experimental preparation helper into an output route. The Figma-inspired workspace redesign will preserve these modes and safety boundaries in its own subsequent PR.
