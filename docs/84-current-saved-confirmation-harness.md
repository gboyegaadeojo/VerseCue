# Current-build saved-passage confirmation harness

This opt-in personal Windows test checks one independently verified existing single-cue KJV passage through the normal workspace. The saved-cue UUID is an external test oracle supplied privately at invocation, not a technical field required in the operator workflow or embedded personal identifier in source.

Both personal-host and disabled-screen-trigger flags are required, along with a verified absolute review-package executable and the expected UUID. Incomplete invocations reject before host access. Independent Audience/Stage checks must remain false, with the intended Look/playlist unchanged. Existing private attempt records across dates block repetition, including after interruption.

The harness prepares/reviews the existing saved passage and loads its thumbnail but never approves or clicks Confirm automatically. Computer Use must inspect the complete text, appearance and target and perform the final normal confirmation. It checks matching readback, then proposes next verse against actual current-output context without sending the proposal or creating another copy. It finishes with local Emergency Stop and never sends Clear or restores another cue.

No microphone, native preparation, formatting repair or new saved copy is requested. A software receipt/readback is not physical-output, church-theme or full-service acceptance. New personal-host results stay in Git-ignored poc/private and must not be published without specific user permission. This code-only deliverable claims syntax/CLI guard validation, not a hardware pass.

Failures record the test step and a content-free private state snapshot before Stop: phase, mode, stopped/dry-run flags, queue/history counts and event codes. No text, UUID, host address or UI message is copied into that snapshot. A wait without matching readback is reported explicitly. Recorded failures still block automatic repetition.
