# Managed native-copy backend

Small PR22 extraction depending on the exact-passage/intent foundation. This adds backend transaction/accounting controls and restricted route readiness. It does not wire the normal workspace, enable automatic native preparation, replace the Windows helper, add a Mac adapter, repair formatting or authorize output.

The saved-copy transaction reads current output identity/text and the focused service playlist before native access, identifies one new presentation, validates exact edition/title/complete ordered cue coverage, then compares output and playlist again. Changed or malformed observations withhold readiness; there is no Clear, restore, delete or blind save retry. Sequential API reads are not an atomic vendor transaction or physical-output proof.

Preparation remains limited to the inspected local Windows21.4.2 profile. Readiness explains unsupported platform/build/LAN routes. When a caller explicitly requests input retention from Confirm and supplies the existing recognition-cancellation callback, preparation retains the authorized input while disarming output. It never acquires a microphone. Existing callers without that option retain paused preparation behavior.

Native attempts are bounded to100 per app run. A separately initialized/injected ledger supports500 forward managed slots across restarts: reserve durably before native access; retain uncertain reservations; record only target hashes and exact saved UUID/fingerprint/clipping metadata; fail closed on corrupt/unwritable accounting. Exact known warnings survive ledger reload. Read-only reconciliation releases accounting only for verified copies absent from a completely checked catalog and never deletes ProPresenter content. Old/untracked copies, backups/trash and physical disk size are outside this quota.

This PR adds the backend interfaces. Desktop initialization/injection, explicit startup inspection for unresolved reservations, native consent ownership, reconciliation controls and normal coordinator wiring remain subsequent integration work. The ledger must be loaded before use; its presence does not grant focus/copy or output consent. Default callbacks cannot establish text/formatting verification.

All294 module tests and JavaScript syntax checks pass on the dependent branch. Tests cover persisted reservations/warnings, quota/reconciliation/corruption/IO failure, exact new-copy identity, output text changes under unchanged identity, playlist changes, cancel/target races and retained-input behavior with synthetic controllers. No real ProPresenter, microphone, new native helper invocation, physical output, latency or Mac native acceptance was tested by this extraction. Matching Mac checks are tracked in the PR before merge.
