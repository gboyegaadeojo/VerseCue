# Saved ProPresenter slide previews

2026-11-19 UTC. PR22 / RF-09. VerseCue can now request a saved slide's actual thumbnail from ProPresenter during passage review. It does not render a substitute Bible slide or supply audience graphics.

## Operator workflow

After preparing a passage, choose a part and click **Load saved slide preview**. The image comes from ProPresenter and appears alongside the existing saved-text review. Each request is deliberate; preparation and recognition do not fetch every image or wait for thumbnails. Selecting another part clears the prior image. Reset, a new review, confirmation or cancellation clears the image source from the review control.

The caption explicitly identifies a **saved-slide thumbnail** and asks the operator to check actual screens and Looks separately. A thumbnail does not prove audience/livestream routing, current physical output, complete formatting or absence of clipping. Vendor caching and presentation metadata do not provide an atomic image/appearance guarantee. Clipping warnings remain blocking, and loading an image cannot check appearance consent, acknowledge a target, arm output, enable Auto or trigger a cue. Text review and ordinary ProPresenter inspection remain available if an image cannot load.

## Verified route and controls

The installed ProPresenter21.4.2 OpenAPI schema documents GET `/v1/presentation/{uuid}/thumbnail/{index}`, with binary PNG/JPEG responses and the `thumbnail_type` query. A read-only personal-host request using `thumbnail_type=png` and `Accept: image/png` returned HTTP200, a400x225 PNG and no output command. The existing saved test copy supplied the image; this is not a current Bible-template or physical-output acceptance result.

The trusted desktop handler accepts a current review token and part position, not a caller-supplied host, URL or arbitrary presentation. The coordinator resolves the exact saved UUID/cue internally and revalidates its complete metadata/fingerprint before and after the image read. A newer reference, target, operation, owner/session change or expired review prevents the response being presented as current. Changed saved metadata withdraws the review. Only one thumbnail lookup runs per coordinator at once.

The connector uses the selected allowlisted target, refuses redirects, requests only PNG and applies a two-second fetch/body deadline. Streaming bytes are capped at2MB; PNG signature/IHDR and dimensions are checked before transfer to the renderer, with4096px edge and4,194,304-pixel limits. SVG/HTML and unexpected MIME are refused. The renderer receives an in-memory PNG data URL under its existing image policy, makes no HTTP requests and saves no image files. Decode failures show an inspection fallback. Application diagnostics contain no image or Bible text.

Tests cover image/MIME/header/dimension/size bounds, streamed cancellation, an actual stalled HTTP body deadline without retries, old-target response rejection, matching passage metadata and newer-reference cancellation. The synthetic desktop check verifies on-demand/part selection, decoded image display, zero renderer HTTP/output triggers, changed-metadata withdrawal, unchecked confirmation and200% review fit. Existing passage and workspace regressions pass separately.

`node scripts/test-slide-preview.cjs [isolated-package-executable]` uses only a generated color-grid PNG, synthetic saved text and a loopback fixture. `node scripts/hil-slide-preview.cjs --authorized-personal-host` is a separate read-only personal ProPresenter check with no native preparation, capture or output; its scoped results must be recorded after execution. Diagnostic screenshots, if explicitly generated by that check, stay private and are not distributed.
